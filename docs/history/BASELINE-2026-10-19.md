# The foundation's baseline, measured 2026-10-19

Measured on the owner's Mac in the Illness Test Graph (Logseq 2.0.2, plugin 0.4.168), with the plugin's own measuring tool. The graph was imported twice, so most journal blocks appear doubled and it is heavier than a normal graph. Every test edit was undone. Each later layer is measured the same way against this baseline.

## What it shows

| | Foundation only | Whole plugin |
| --- | --- | --- |
| Time measured | 316.5 s, 13 pages, 3 record edits | 199.2 s, 12 pages, 3 record edits |
| The plugin's own work | none recorded (no watcher, update or stylesheet rows) | screen watcher 388 calls; `refreshCues` 34 runs, 30.2 s in all, 0.89 s each on average, 1.55 s at worst |
| Long frames (Logseq and the plugin together) | 83, 7.7 s in all, about 1.5 s a minute, worst 0.53 s | 116, 12.4 s in all, about 3.7 s a minute, worst 1.26 s |
| Layout shift score | 0.077 | 0.652 |
| Reload | stuck on “Load plugin”; a reload of the whole window fixed it | under 3 s |

- The foundation costs nothing measurable: what is left with Foundation only on is Logseq's own drawing.
- Almost all of the whole plugin's cost is one step, `refreshCues` (the cues after blocks, `parts/links.js`, layer 3), at about 0.9 s a run. That is the first thing to rebuild with speed in mind.
- The page moves much more with the whole plugin (layout shift 0.65 against 0.08): the page's blocks, the tabs under a page and the property pills move after they are drawn.
