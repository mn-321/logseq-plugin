### 4. Where design can take the remaining friction out

The plugin can register shortcuts and palette commands, read and write the block in edit (`toSavedRange` in `parts/editor.js` maps the editor's text onto the saved text), open a list under the caret and hold Enter and the arrows back from Logseq while it is open (`parts/inline-props.js`, `onKey`), draw a dashed ghost in a record's own pill, show the dark Undo bar, read the whole graph through datascript with a 30-second cache (`graphWide`), mark Logseq's own pickers as they are drawn (`updatePickerMarks`, `updatePropertyPicker` in `parts/links.js`) and put a small element into them (the type icon), and draw its own lists with one row renderer (`ripRowHtml`). It cannot change Logseq's editor, its data model, the order of a picker's rows or the contents of a table, and the plugin API refuses every icon value. A property made through the API belongs to the plugin, not to me, so a new property always comes from Logseq's Add property. A text search over every block is not cheap in my real graph. Within that, directions I want worked through, each judged by keys saved against the chance of a wrong write, and each starting from what Logseq already does halfway:

- **Capture that files itself.** A Meeting on the journal that names Priya in prose, where Priya Nair is a Person and attendees takes Persons: the plugin proposes the relation, as a ghost in the pill, and `j` writes it. - **The rule made the easy path.** A free-text value one letter off from one already used proposes the existing one (the line list does this for text fields; where else does drift happen?). A `[[` on a name that is a Person's first name proposes the Person. A tag typed with `#` whose parent I usually also use says so. - **The two Date paths made one.** Journal day as date and `date::` both write a Date; one asks with a ghost and `j`, the other lists days and writes on Enter. One grammar of asking, one bar, one setting shape; say which survives.
- **The pickers I have not reached.** The `#` tag picker, the property value picker on a pill, the Set tags list: the same marks, the same dashed "new", and the New row never the default when a match exists. Say which Logseq re-renders in a way that holds marks and which does not.
- **The link box's missing rows.** Blocks are not listed because a text search over every block is a different thing; say whether Logseq's own search (the API the search window uses) can feed the box with marked block rows at a cost I would accept, or whether this stays out.
- **One list, one box, one bar, one keyboard.** The line list, the link box, the search window's rows, the Todos rows and the tree rows are five drawings of "a row in a list the plugin made". The modal, the rich-copy card, the merge box, the Todos window and the settings window are five drawings of "the plugin is asking". The Undo bar is written twice. The keys differ by view.
